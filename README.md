## DBaaS Containerlab Emulation

Проект предназначен для эмуляции высокодоступного кластера PostgreSQL в контейнеризированной среде с использованием Containerlab. Архитектура включает репликацию данных, автоматическое управление отказоустойчивостью и балансировку нагрузки.

### Архитектура

Топология состоит из следующих компонентов:

- **PostgreSQL кластер** (3 узла): один мастер и две реплики для обеспечения высокой доступности
- **Patroni**: управление отказоустойчивостью и автоматическое переключение между мастером и репликами
- **etcd**: распределённое хранилище конфигурации для координации состояния кластера
- **HAProxy**: балансировка нагрузки и маршрутизация запросов к доступному узлу
- **FRRouting**: маршрутизация сетевого трафика между компонентами

### Требования

- Containerlab установлен и настроен
- Docker для запуска контейнеров
- Linux хост для развёртывания

### Использование

Запустите топологию командой:

```
sudo clab deploy -t topology.clab.yml
```

Остановка топологии:

```
sudo clab destroy -t topology.clab.yml
```

### Структура проекта

- `topology.clab.yml` - определение топологии всех узлов и связей
- `Dockerfile.postgres` - образ PostgreSQL с Patroni и etcd
- `configs/` - конфигурационные файлы для узлов (Patroni, FRRouting)

### Компоненты конфигурации

Каждый узел PostgreSQL настроен на работу в кластере с координацией через etcd. Patroni обеспечивает автоматическое управление ролями узлов и восстановление при отказах. HAProxy выполняет функцию единой точки входа с автоматической переориентацией на здоровый узел.
